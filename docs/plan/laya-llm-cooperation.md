# Laya / LLM 协作推进计划

更新：2026-09-30。此计划同时覆盖家居与 IP 团队，两个业务契约保持独立。

## 目标与边界

Agent 保存权威会话上下文、预算和版本；Laya 利用当前公开上下文提出快速、受限的决策；
LLM 处理复杂输入或被拒答的请求；业务执行仍经现有状态检查和执行权威。
不因“有上下文”直接绕过 Laya，不将模型接收上下文等同于能力已经验收。

## 协作分工（供用户转发 Claude Code）

Claude Code 负责 eidolon_models 的 Laya 服务及部署重构、模型评测：

1. 保持家居与参与决策现有 HTTP / SDK 契约兼容，交付部署提交、模型/profile/阈值。
2. 交付该部署版本 NPU p-dev 逐条结果、真实拒答集合（ID、原因、输入/数据哈希），
   说明 PyTorch/NPU 差异；不把旧版本约89%覆盖当成线上比例，也不预设一定是67条。
3. 交付参与决策规范版本和澄清原因到有界任务说明的来源。
4. 说明现有家居上下文入口和已验证能力；模型不维护第二份会话权威。
5. 验证 NPU、并发/忙碌、取消后的恢复与资源占用；正式共享Host重启/发布先协调。
6. 不同时修改 Agent 决策组合、LLM兜底或家居上下文路由；若需SDK变更先给契约差异。
