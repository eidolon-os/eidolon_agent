# 家居连续对话协作验收（2026-09-29）

## 本次落地

Agent继续拥有唯一HomeContext、Proposal及语义版本。LLM理解指代、缺失信息、取消、修正和开放目标；Laya处理其已训练的单句解释任务。上下文存在与否不再直接决定模型：本句具有独立、完整且唯一的语义依据时，仍可走Laya。

独立性证据复用既有RulesInterpreter的逐段解释机制，增加严格模式：整句必须被解释、不能夹带未解释文本或闲聊片段、目标必须明确，不能从设备所在房间或动作维度猜目标。这个模式不新增关键词表，不执行命令、不生成上下文。Domain通过现有解释端口注入它，不导入infra。

Laya提案还须通过原置信度门槛、SDK契约校验，并与独立解释一致；任何分歧、低置信度或超时均携带原始上下文交给LLM。歧义、指代、否定等不能取得独立性证据的请求直接LLM，避免先支付800ms的小模型等待。旧上下文在新提案确认前保留；执行前继续重读注册和检查语义版本。

这仍是范围明确的过渡方案：严格解释器覆盖之外的自然表达直接LLM；重复解释有成本，但没有新增路由模型或私有记忆。**尚未实现经训练校准的Laya多轮决策，也不能称为完美协作。**要移除严格模式，需要独立的任务范围/上下文能力评测支持，不能凭新提示词或单一阈值放开。

## 真实模型验收

仅调用真实Mac Laya torch/MPS和现有DeepSeek LLM；目录来自SDK样例，执行端为内存测试替身，未控制生产设备。

- 7条连续场景共17轮：修正后17/17符合预期。打开窗帘→关闭窗帘两轮均只调用Laya，分别418.3ms、157.7ms；待关闭主灯→打开主卧灯切换动作，仅调用Laya，270.8ms。以上是测试用例耗时，不是ASR到屏幕端到端时延。
- 指代、候选补全、相对调节、取消、缺失焦点、改口、话题切换均经LLM完成。两条LLM请求出现6.16秒和7.03秒耗时，体验未全部达标；保留8秒总预算，没有为了报告删掉离群点。
- 首轮发现LLM将“不要关闭主卧灯”转成打开动作，已保留失败证据。补充了否定不等于反向执行的模型指令；另外12条否定/取消回归全部无设备动作。有限测试不能证明LLM永不出错。
- 直接向r14增加scope问题失败：它以0.8702将“打开它”判为独立指令，以0.9733将含否定与改口的复合句判为单一完整指令。该能力没有上线，未通过调阈值掩盖失败。
- 新增understanding与execution阶段耗时日志，按turn_id关联。execution包含Agent执行适配器及Hub往返，不应解释为纯Hub计算时间。

## 清理

Channel不再暴露通用execute方法，仅保留触屏输入到Hub的翻译与面板投影。旧VirtualProvider、Data注册读取、旧执行HTTP入口已在迁移提交删除；本次清理其残留字节码。Mac旧Channel家居SQLite及上一轮临时归档删除。Channel自身provider.sqlite3属于通道管理，仍保留。

迁移工具仍用于其他尚未升级的Host，不能因Mac完成迁移就删除全局迁移支持。所有新设备执行与状态唯一归Hub。
