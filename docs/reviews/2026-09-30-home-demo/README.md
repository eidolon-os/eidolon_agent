当前未达到客户 demo 放行条件。范围仅为智能家居灵活交互；多角色伙伴另行验收，不作为本次依赖。

本次没有部署候选，也没有改变产品模型、板上家居模式或重启产品栈。所有动作评测使用虚拟执行器，没有操作真实设备。MPS 结果不能证明 NPU 或语音端到端性能。

## 项目边界与下一步

1. **Agent：优先解决语义稳定性。** 保存失败轮次的原始结构化响应，区分模型未给有效提案、适配解析失败和上下文缺失。复用现有 schema、校验及一次 LLM 兜底；依据根因修正，不追加关键词阻断或第二套会话状态。冻结版本后重跑全部 46 组，并加入未参与调试的自然改写；检查逐轮动作、澄清内容、取消及重复执行，而不只看总分。
2. **Models / Claude：独立完成 c4 NPU 验证。** 提供模型、校准、continuation 契约及运行版本标识，证明板上实际使用 NPU；记录单句及 pick/follow 一致性、热身与稳态延迟、并发下 p50/p95/最大值和错误。训练问题独立处理，不用 Agent 特例掩盖。现有 MPS 结果不能替代这项验收。
3. **Ops / Agent：两项通过后固定版本发布。** 复用现有部署与 readiness 流程，确认唯一服务地址及回滚版本，再进行两轮真机彩排。估计需要约一个工作日，前提是前两项已通过；目前不能承诺客户 demo 日期。

## 冻结的演示范围与放行门槛

- 单句操作、多候选选择、补充动作、取消、取消后新请求、更换目标、代词承接、相对/绝对参数、多设备操作、状态查询后继续操作，以及转述/假设/否定与真正请求的区分。
- 固定回归集逐轮行为正确；不允许误执行、重复执行或凭空补全设备。无明确意图时自然澄清；已补齐的信息不重复询问。
- 故障路径有明确反馈；模型不可用不能静默，也不能误报设备已执行。
- 真机覆盖语音结束 → Agent 路由 → Hub → Provider 回执 → 客户端状态更新，保存同一轮关联证据及各阶段耗时。应用 readiness 通过不等于交互验收通过。
- 沿用既有产品性能目标，不用本次 MPS 或纯文本数字替代 OPi 端到端指标，也不因 LLM 慢而降低标准。分别报告快路径和 LLM 路径的 p50/p95、超时、冷启动及并发影响。
- 当前家电 Provider 为虚拟设备，客户演示时明确这一边界。已有“首期不新增门锁专用确认”决策不在本次擅自变更。

本次只读观测的板上版本为 `rk3588-p4-route-20260929-1`、readiness 为 `app_ready`，见 `host-observation.json`；这不代表 c4 或本次候选已部署。

## 后续定位：目标切换（2026-09-30）

依用户要求，Claude 的工作由用户另行通知，本轮只推进 Agent。

- 使用旧失败报告中完全相同的用户话语、上下文和 SDK 样例设备，请求现有 Flash：两批各 5 次均返回有效的卧室候选、关闭动作。第二批原始消息、工具响应及用量保存在 `target-probe.json`。没有复现旧失败，不能断言其根因。
- 第二批另外经过真实 LLM → Agent → 虚拟 Provider 做了两轮三句交互：打开客厅主灯 → 卧室的也关掉 → 床头灯。均为 executed → ambiguous → executed，实际命令只有客厅主灯 on 和床头灯 off 各一次。此项隔离 Agent/LLM：首句由规则解释，后续由真实 LLM 解释，没有调用 Laya，不能算 Laya 协作或 NPU 验收。
- 新增确定性回归验证同一工具响应形状在 Agent 内保留候选和新动作、等待选择且不重复执行。它验证软件边界，不代表模型准确率。
- 评测脚本保存合成案例的 LLM 消息、完整工具响应、文本、结束原因和用量；生产日志仅区分 `no_tool_call` 与 `null_proposal`，不记录原始用户文本。下一次失败可据此定位，避免再凭最终卡片推断模型行为。
- 评分支持逐轮 `expected_outcomes`（每轮允许结果的数组），内置目标切换案例必须返回 ambiguous / clarification。不能再仅凭“无多余命令且没报错”判定这一轮成功。旧 45/46 报告不重写、不升级为通过。

| 责任方 | 负责内容 | 交接依据 |

上下文由 Agent 管理并按契约提供给 Laya；Laya 承担其声明支持的快速上下文判断。超出契约、拒答、低置信度、超时或返回无效结果，进入现有 LLM 兜底。两者输出都经过现有校验和执行边界；不能用模型猜测替代设备状态或执行回执。具体阈值随锁定模型的校准契约核对，不默认沿用试验版本。

模型交接后先核对 revision、校准、题目/出口及状态格式是否与当前适配一致，再跑虚拟设备回归；通过后固定发布并做真机验收。若契约变化，仅在 Models/SDK 契约和 Agent 适配边界处理，不把训练实现引入 Agent，也不让模型服务接管会话状态或设备执行。

不主动协调或改动 Claude 的工作，不轮询其进度。现有 `7b695ba8` 仅是已测试候选，不预先认定为最终锁定模型；产品部署维持现状。
