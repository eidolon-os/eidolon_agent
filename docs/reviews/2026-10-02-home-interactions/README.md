## Agent与产品下一步

1. **先处理目标一致性。** 当前follow把选项映射到previous.targets，SDK只能校验该目标是否存在且支持动作。因此一个语义错误但结构合法的提案能够执行。复用完整设备目录、已有目标解析/独立理解机制，评审如何保证明确新目标不被旧焦点覆盖；需要同时覆盖别名、否定、改口及部分目标，不能只加设备关键词判断。
2. **再评审减少不必要LLM调用。** 现有严格独立解释器能完整读出「开音箱」「关掉音箱」，却读不完整「把音箱打开」「再关闭电视」；这些离线输出保存在independent-witness.json。复用该机制调整入口有价值，但单纯提前它只能覆盖一部分问题，不能宣称已经解决自然语言的目标冲突。完整命令与依赖上下文的话语应分别走合适的现有任务；不能默认每轮串行增加一次单句调用。
3. **统一Laya与LLM的语义约定。** 明确只排除候选、取消后新请求、多目标代词的政策，并映射到现有工具及评测。对LLM已拿到上下文却判断错误的问题，优先定位提示词/工具表达与模型稳定性，避免再建一套会话记忆。
4. **异构多动作先决定产品范围。** 若本轮demo不支持，应在执行前清楚说明或澄清，避免模型将多个动作压扁成同一动作。若支持，沿SDK命令列表和现有规划/执行边界扩展提案表示，单独评审，不能用一段LLM提示词假装现有schema已经具备能力。

本轮按用户要求完成观测、模拟和归因，未把探索结论直接改成新的生产路由。客户demo暂不据此放行，应先闭环已稳定复现的错目标执行，再跑这些保留回归及新的自然改写。
