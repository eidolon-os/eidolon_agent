# Memory 回答证据边界复核 — 2026-10-08

当前改动只增强 ContextCompiler 已有 retrieved-memory 提示，要求核对人物、关系、事件和时间，禁止跨记忆拼造经历；区分当前用户提供的新信息和对历史记忆的询问。没有新增检索器、模型调用、查询重写、阈值或事实存储。正常服务路径没有新增网络请求。

## 验证

使用已授权的 40 轮合成语料的冻结 MCP 上下文，选择 9 道原无答案标签题和品种、年龄、播客 3 道正例，经当前 ContextCompiler 编译后调用既有 DeepSeek 配置。12 题全部正常结束（finish_reason=stop），无空回答。实际为最小 persona + memory port 替身 + 真实编译器/模型，并非部署 Agent 端到端验收，也不是留出集。

人工逐条核对：品种、播客回答与证据一致；北京出差、承诺等没有被编造为已发生的具体经历。用户本轮说“跟客户吵架了”属于新信息，正常回应不应要求先有历史记录。“前任的事”和“我爸去世的事”的回复没有复述删除内容，但本探针不能代替删除生命周期测试。

**未通过项**：狗的年龄仍未召回；模型回答“铁锤的年龄我这边没有记录”，仍有把本轮未找到泛化为未记录的风险。问鸟时说“鸟的事没听说过”也不够准确。此提示不能保证回答可靠，不能报告为 9/9 拒答通过，更不能报告修复了年龄召回。禁止为这些开发题继续堆提示词或特例。

首次试案使用英文补充规则，年龄回答“年龄没提过”；600 token 输出额度下鸟问题为空文本，当时未记录 finish_reason，不能确定原因。最终试案改成中文规则，并将探针输出额度改为 2048；因此不能把两次输出差异作严格单因素因果证明。两轮输入和回答都保留。

编译器/上下文及跨模块回归 81 项通过，Ruff 通过。Memory 检索评分保留原 JSON 字段和算法，只将展示名称改为“无答案标签题的空召回”，明确它不是最终回答正确率。

## 收敛边界

保留已有 canonical ledger、权限、删除、取消任务修复；本次没有改变召回数量或默认排序。基础工程修复与产品质量/性能验收分开：年龄漏召回、跨轮指代、回答的缺证据措辞、三段可读时效和既有规模 SLO 缺口均未因本次提示修订而解决。当前结果是有限交付，不能宣布 Memory 产品整体达标。
